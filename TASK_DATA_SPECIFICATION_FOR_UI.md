# 📦 Task Generation Data Specification & UI Integration Guide
### For SIH Frontend Dashboard Developer

This document details the exact structure, fields, coordinate system, and lifecycle states of tasks generated by the AMR fleet system.

---

## 1. 📋 Task Data Schema (JSON Payload)

When a task is generated, here is the exact data structure:

```json
{
  "task_id": "rnd_task_001",
  "priority": 75,
  "pickup": {
    "x": -19.99,
    "y": -17.60,
    "theta": 0.0,
    "rack_id": "RACK_WEST_SOUTH_01",
    "item_type": "Servo Motors"
  },
  "dropoff": {
    "x": -11.35,
    "y": -6.11,
    "theta": 0.0,
    "station_id": "DROPOFF_STATION_A",
    "zone": "DISPATCH_BAY_1"
  },
  "dwell_times": {
    "pickup_wait_s": 3.0,
    "dropoff_wait_s": 3.0
  },
  "status": "ANNOUNCED",
  "assigned_robot_id": null,
  "winning_bid": null,
  "created_at_epoch": 1789187770.719,
  "expires_at_epoch": 1789188070.719
}
```

## 2. 🧩 Field-by-Field Breakdown

| Field Name | Type | Unit / Range | Description |
| :--- | :--- | :--- | :--- |
| `task_id` | `string` | e.g. `"rnd_task_001"` | Unique identifier for the task. |
| `priority` | `number` (int) | `1` (low) to `100` (critical) | Task urgency / priority weighting in CBBA auction. |
| `pickup.x` | `number` (float)| `-22.5` to `+22.5` meters | Map X coordinate for pickup rack. |
| `pickup.y` | `number` (float)| `-30.0` to `+30.0` meters | Map Y coordinate for pickup rack. |
| `pickup.theta` | `number` (float)| `0.0` to `6.28` radians | Approach orientation angle at pickup. |
| `dropoff.x` | `number` (float)| `-22.5` to `+22.5` meters | Map X coordinate for dropoff dispatch station. |
| `dropoff.y` | `number` (float)| `-30.0` to `+30.0` meters | Map Y coordinate for dropoff dispatch station. |
| `dropoff.theta` | `number` (float)| `0.0` to `6.28` radians | Approach orientation angle at dropoff. |
| `pickup_wait_s`| `number` (float)| `seconds` (typically 3.0s) | Loading dwell time once AMR arrives at pickup. |
| `dropoff_wait_s`| `number` (float)| `seconds` (typically 3.0s)| Unloading dwell time once AMR arrives at dropoff. |
| `status` | `string` | See Lifecycle States below | Current execution phase of this task. |
| `assigned_robot_id`| `string` \| `null`| e.g. `"robot_1"` | Robot awarded the task via CBBA auction. |
| `winning_bid` | `number` \| `null`| e.g. `104.46` | The winning CBBA cost value. |
| `created_at_epoch` | `number` (float)| Unix timestamp (s) | Task announcement timestamp. |

## 3. 🗺️ Map Coordinate System & UI Canvas Scaling

The warehouse map uses standard ROS metric coordinates:
- **Origin `(0, 0)`**: Warehouse Center.
- **X Axis**: Horizontal span `[-22.5m, +22.5m]` (Total Width = **45.0m**).
- **Y Axis**: Vertical span `[-30.0m, +30.0m]` (Total Height = **60.0m**).

### Converting World Metres `(x, y)` to UI Canvas Pixels `(px, py)`:
```javascript
function worldToCanvas(worldX, worldY, canvasWidth, canvasHeight) {
  const mapOriginX = -22.5;
  const mapOriginY = -30.0;
  const mapWidthM = 45.0;
  const mapHeightM = 60.0;

  // Scale factors
  const scaleX = canvasWidth / mapWidthM;
  const scaleY = canvasHeight / mapHeightM;

  const px = (worldX - mapOriginX) * scaleX;
  // Flip Y because canvas origin (0, 0) is top-left, ROS Y is pointing up
  const py = canvasHeight - ((worldY - mapOriginY) * scaleY);

  return { px, py };
}
```

## 4. 🔄 Task Lifecycle States (For UI Badges & Timelines)

As the fleet works, the task transitions through the following statuses:

```
 ┌───────────────┐
 │   ANNOUNCED   │  (Generated by RandomTaskGeneratorNode, broadcasted to fleet)
 └───────┬───────┘
         │
         ▼
 ┌───────────────┐
 │  CBBA_AUCTION │  (AMRs submit bids; consensus quorum resolution in progress)
 └───────┬───────┘
         │
         ▼
 ┌───────────────┐
 │   ASSIGNED    │  (Winner chosen, e.g. robot_1; TaskExecutor accepts)
 └───────┬───────┘
         │
         ▼
 ┌───────────────────┐
 │  EN_ROUTE_PICKUP  │  (phase = 0: Robot moving along WHCA* route to pickup)
 └───────┬───────────┘
         │
         ▼
 ┌───────────────────┐
 │    PICKUP_WAIT    │  (phase = 1: At pickup station, 3.0s dwell countdown)
 └───────┬───────────┘
         │
         ▼
 ┌───────────────────┐
 │ EN_ROUTE_DROPOFF  │  (phase = 2: Robot moving along WHCA* route to dropoff)
 └───────┬───────────┘
         │
         ▼
 ┌───────────────────┐
 │   DROPOFF_WAIT    │  (phase = 3: At dropoff station, 3.0s dwell countdown)
 └───────┬───────────┘
         │
         ▼
 ┌───────────────┐
 │   COMPLETED   │  (phase = 4: Task finished; telemetry logged; robot free)
 └───────────────┘
```

### UI Badge Color Suggestions:
- `ANNOUNCED` / `CBBA_AUCTION`: 🟣 **Purple / Magenta** (`#a855f7`)
- `ASSIGNED` / `EN_ROUTE_PICKUP`: 🔵 **Blue** (`#3b82f6`)
- `PICKUP_WAIT` / `DROPOFF_WAIT`: 🟡 **Yellow / Amber** (`#f59e0b`)
- `EN_ROUTE_DROPOFF`: 🟦 **Cyan** (`#06b6d4`)
- `COMPLETED`: 🟢 **Green** (`#10b981`)
- `FAILED`: 🔴 **Red** (`#ef4444`)

## 5. 📡 Data Ingestion Endpoints (How Frontend Receives It)

### Option A: WebSocket / Telemetry Bridge JSON (`/fleet/dashboard_telemetry`)
If the frontend connects via WebSocket to the dashboard bridge, it receives:
```json
{
  "robots": {
    "robot_1": { "x": -5.25, "y": -22.60, "theta": 1.57 },
    "robot_2": { "x": -3.75, "y": -29.55, "theta": 1.57 },
    "robot_3": { "x": -2.25, "y": -29.55, "theta": 1.57 },
    "robot_4": { "x": -0.75, "y": -25.67, "theta": 1.57 }
  },
  "health": {
    "robot_1": { "battery": 92.4, "safe": true }
  },
  "tasks": [
    {
      "task_id": "rnd_task_001",
      "priority": 75,
      "status": "EN_ROUTE_PICKUP",
      "assigned_robot": "robot_1",
      "pickup": { "x": -19.99, "y": -17.60 },
      "dropoff": { "x": -11.35, "y": -6.11 }
    }
  ],
  "events": [
    { "type": "task", "detail": "rnd_task_001->robot_1@1" },
    { "type": "corridor", "detail": "robot_1:NC-SOUTH-WEST-06:ENTER" }
  ]
}
```

### Option B: ROS 2 Topics (via `rosbridge_websocket` or `rclnodejs`):
- `/fleet/task_announcement` (`sih_amr_interfaces/msg/TaskAnnouncement`)
- `/fleet/task_consensus` (`sih_amr_interfaces/msg/TaskConsensus`)
- `/{robot_id}/task_execution_status` (`sih_amr_interfaces/msg/TaskExecutionStatus`)
